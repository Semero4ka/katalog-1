# Каталог товаров и накладные — PWA

## Что внутри
- Статический PWA-каталог, подготовленный на основе предоставленных Excel-файлов.
- Товары сгруппированы по категориям-заголовкам исходного прайс-листа; строки-заголовки не отображаются как товары.
- Цены в рублях; остатки объединены по нормализованным названиям.
- Корзина с локальным резервированием остатков.
- Заказы со статусами «Новый» / «Завершён», повторное открытие накладной и удаление заказа.
- Редактируемая накладная: поставщик, покупатель, строки товаров, количество, цена, сумма, подписи. Длинные наименования переносятся на новые строки в редакторе и в печатной версии/PDF.
- Добавление фотографии товара через клик по миниатюре; полноразмерный просмотр.
- Импорт прайса и остатков из Excel в интерфейсе.
- Экспорт/восстановление резервной копии, включая заказы и фото.
- PWA manifest и service worker.

## Размещение на GitHub Pages
1. Создайте новый репозиторий GitHub.
2. Загрузите в корень репозитория все файлы из архива, включая `catalog.json`, `index.html`, `app.js`, `styles.css`, `manifest.webmanifest`, `service-worker.js`.
3. В Settings → Pages выберите публикацию из ветки `main`, папка `/ (root)`.
4. Откройте опубликованный HTTPS-адрес. При первом запуске нужна сеть для загрузки библиотеки Excel (SheetJS с CDN); каталог после загрузки кешируется.
5. Для установки на компьютер/телефон откройте сайт в поддерживаемом браузере и выберите «Установить приложение» / «Добавить на главный экран».

## Важные ограничения этой версии
- Данные хранятся локально в браузере на одном устройстве (IndexedDB), не в GitHub. Экспортируйте резервную копию регулярно.
- Фото добавляются в браузере и включаются в резервную копию, но сами по себе не загружаются в репозиторий GitHub.
- Автоматической отправки заказов по электронной почте и прямой интеграции с 1С нет: для этого нужен адресат/формат обмена и, как правило, серверный компонент или отдельный обменный файл.
- Накладная печатается через диалог браузера; там можно выбрать «Сохранить как PDF».
- Исходный прайс-лист содержит строки товаров и заголовки категорий; категории определяются по заголовкам из исходного файла. Остатки импортируются из столбца «Итого» (а не «склад») и сопоставляются по нормализованному названию с дополнительной проверкой категории. До первой загрузки файла остаток может быть не указан; при импорте полного снимка отсутствующие позиции и строки с пустым количеством получают нулевой остаток.
- Каждый успешный импорт таблицы остатков полностью заменяет текущий снимок: значения берутся из колонки «Итого», товары сопоставляются сначала по нормализованному точному названию, затем по более мягкому ключу только при однозначном совпадении с учётом категории. Неоднозначные совпадения, повторные строки и не найденные позиции с ненулевым количеством останавливают импорт, а прежние остатки сохраняются. Не найденные строки с нулевым количеством можно пропустить; пустое значение «Итого» считается нулём и отдельно отражается в отчёте. Товары, отсутствующие в файле остатков, остаются в каталоге с нулевым остатком. Резервы из корзины и заказов учитываются отдельно, доступный остаток не отображается отрицательным.

## Источники исходных данных
- `Prays_17 (1).xlsx` — цены; первые 4 строки являются заголовком отчёта.
- `ostatki_17.xlsx` — остатки; первые 3 строки являются заголовком отчёта.


### Надёжный импорт прайс-листа

- Перед импортом приложение проверяет, что в выбранном Excel-файле распознаются строки товаров и цен.
- Сопоставление выполняется по нормализованному названию; если точного совпадения нет, применяется осторожное сравнение с учётом пунктуации и пробелов. Неоднозначные совпадения пропускаются, чтобы не менять цену не того товара и не создавать дубли.
- Новый прайс полностью заменяет каталог: товары, которых нет в новом файле, удаляются из текущего каталога. Для совпадающих товаров сохраняются идентификатор, фото и текущий остаток; для новых товаров создаются новые записи. Исторические заказы и настройки остаются. Корзина очищается от товаров, отсутствующих в новом каталоге.
- Перед заменой приложение просит подтверждение и отдельно предупреждает, если новый файл содержит существенно меньше товаров, чем текущий каталог.
- После импорта формируется отчёт о подорожавших, подешевевших, новых и удалённых товарах, со старой и новой ценой, разницей в рублях и процентах. Доступны поиск, фильтры и сортировка. Сохраняется история последних 30 загрузок с датами. История включается в резервную копию.
- Версия Service Worker обновлена, чтобы браузер мог загрузить новый код приложения. Если сайт долго открыт во вкладке, перезагрузите его после публикации.


### Фотографии товаров (версия с оптимизацией)

- Фотографии хранятся отдельно от записей каталога в IndexedDB, поэтому при открытии списка товаров браузеру не нужно загружать все изображения в оперативную память.
- При добавлении фото приложение уменьшает изображение до максимальной стороны 1000 пикселей и сохраняет сжатую версию.
- Миниатюры загружаются по мере прокрутки каталога.
- При первом запуске обновлённой версии фотографии, добавленные в предыдущих версиях, автоматически переносятся в отдельное хранилище и по возможности сжимаются. Миграция не очищает каталог, заказы, остатки или историю цен. Не закрывайте вкладку, пока в счётчике товаров отображается «Оптимизация фотографий».
- Резервная копия включает фотографии; старые резервные копии также поддерживаются. Перед любыми крупными изменениями всё равно рекомендуется выгрузить резервную копию, если приложение открывается.


### Импорт остатков — проверка совпадений

- Перед импортом приложение ищет в первых строках заголовок «Итого» и читает значения именно из этого столбца; если заголовок отсутствует или встречается неоднозначно, импорт останавливается.
- Для сопоставления используются точное нормализованное имя и более мягкий ключ. При нескольких совпадениях приложение учитывает категорию и не выбирает произвольный первый товар.
- Если положительный остаток не найден в каталоге, найдено несколько возможных товаров, обнаружена повторная строка или некорректное числовое значение, импорт останавливается без изменения текущих остатков. В сообщении выводятся примеры строк для проверки.
- Пустые ячейки «Итого» считаются нулевым количеством и перечисляются отдельно. При успешном импорте формируется полный снимок остатков; товары из каталога, отсутствующие в файле, получают ноль.

### Создание накладных — защита от повторного оформления

- Сохранение нового заказа и очистка корзины выполняются одной транзакцией IndexedDB. Либо сохраняются и заказ, и пустая корзина, либо не сохраняется ни одно из изменений.
- Во время оформления кнопка блокируется, повторные нажатия игнорируются, а добавление/удаление товаров временно блокируется до завершения операции.
- Новые заказы получают идентификаторы на основе UUID (с резервным генератором), а создаются через `add`, а не `put`: совпавший идентификатор не может молча перезаписать существующую накладную.
- После успешного оформления приложение показывает номер созданной накладной и переходит к ней. Корзина очищается только после подтверждения завершения транзакции.
